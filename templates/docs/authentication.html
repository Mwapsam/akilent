API keys

Owners and admins create keys under Settings › API keys. Give each key a name, choose what it can do (its scopes), whether it's a live or test key, and optionally when it expires. Keys look like ak_live_… (or ak_test_…) and are shown to you once, at creation — {{ site.app_name|default:"Automator" }} stores only a hash, not the plaintext, so if you lose it, create a new key and revoke the old one.

Send it on every request as either header:

X-Api-Key: ak_live_xxxxxxxxxxxxxxxxxxxxxxxx
# or
Authorization: Bearer ak_live_xxxxxxxxxxxxxxxxxxxxxxxx

A business can have several keys at once. To rotate without downtime, create the new key, update your callers, then revoke the old one. A revoked or expired key stops working immediately.

A missing or invalid key returns 401 with {"error": {"code": "authentication_failed", ...}}. Repeated invalid attempts from the same client are temporarily locked out (429) as a brute-force guard.

SMTP relay credentials
