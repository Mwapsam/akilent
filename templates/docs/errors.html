Every error response from /api/v1/ uses the same envelope:

{
  "error": {
    "code": "unverified_domain",
    "message": "'yourdomain.com' is not a verified sending domain for this account",
    "request_id": "3f9c1e0b8a7d4e2f9c1e0b8a7d4e2f9c",
    "docs_url": "https://akilent.com/docs/errors#unverified_domain"
  }
}

request_id is also returned as the X-Request-Id response header on every call (echoed from your request if you send one) — quote it when contacting support. docs_url is present for catalogued codes and links straight to the relevant row below.

Always branch your error handling on code, not the human-readable message text — messages may be reworded, codes won't change without a version bump (see Versioning & changelog).

Idempotency

Send an Idempotency-Key header (any unique string, e.g. a UUID) on POST requests. A retried call with the same key and the same body returns the original response and does not send a second time; the same key with a different body returns 409 idempotency_key_reuse. Keys are remembered for 24 hours. The official SDKs generate one per call automatically.

See Rate limits for the difference between the 429 (rate) and 403 emails (volume) cases — they're two separate limits.
