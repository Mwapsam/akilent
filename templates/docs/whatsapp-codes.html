Send login, sign-up and payment-confirmation codes to your customers on WhatsApp. Your system makes the code and checks it when the customer types it back. Akilent only delivers it, using your approved Authentication template. Meta writes the wording, for example "482913 is your verification code", with a Copy code button.

You need a connected WhatsApp number, an approved Authentication template (create one under Templates → WhatsApp), and an API key with the messages:send scope, which every key has.

Send a code

curl -X POST https://akilent.com/api/v1/whatsapp/verification-codes \
  -H "Authorization: Bearer ak_live_xxxxxxxxxxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: login-8841-attempt-1" \
  -d '{ "to": "+260971234567", "code": "482913" }'
import requests

resp = requests.post(
    "https://akilent.com/api/v1/whatsapp/verification-codes",
    headers={
        "Authorization": "Bearer ak_live_xxxxxxxxxxxxxxxxxxxxxxxx",
        "Idempotency-Key": "login-8841-attempt-1",
    },
    json={"to": "+260971234567", "code": "482913"},
)
resp.raise_for_status()
print(resp.json())
FieldRequiredNotes
toYesThe customer's WhatsApp number with its country code.
codeYes4 to 15 letters or numbers, no spaces.
templateNoThe Authentication template's name. Defaults to your newest approved one.
languageNoThe template's language code, e.g. en. Only needed when the same name exists in several languages.

Response

HTTP/1.1 202 Accepted

{
  "id": "5120",
  "status": "queued",
  "to": "+260971234567",
  "template": "login_code",
  "language": "en",
  "created_at": "2026-09-26T09:14:03+00:00",
  "sent_at": null
}

Check delivery

GET /api/v1/whatsapp/verification-codes/5120

status moves from queued to sent, delivered and read as WhatsApp reports back. A failed code also has an error with a code and a plain-language message. If WhatsApp fails, offer the customer another way to get a code, such as SMS or email.

Rules

  • The code is not kept. Akilent blanks it out once it has been sent, or has failed for good. Nobody at your business can read it later.
  • Late codes are dropped. A code that couldn't go out before the template's expiry (10 minutes if the template doesn't say) fails with CODE_EXPIRED instead of arriving late.
  • At most 5 codes per number per hour. More returns 429 too_many_codes, so a leaked key can't be used to flood people.
  • Codes don't appear in the inbox. They're system messages, not conversations.
  • STOP doesn't block them. The customer asked for the code, so it's sent even if they once opted out of your messages.
  • Test keys send nothing. A key starting ak_test_ checks the request and returns "status": "test".
  • Retries are safe. Send the same Idempotency-Key and you get the first result back instead of a second message.
