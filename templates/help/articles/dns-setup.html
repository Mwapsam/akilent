DNS records tell the world that mail from your domain is genuinely yours. After you add a domain, its card on the Domains page lists every record it needs. Copy each one into your DNS host, then click Check DNS.

The records you'll add

RecordTypeWhat it does
VerificationTXTProves you own the domain so we can switch it on. Required.
DKIMCNAME (three of them) or TXTSigns your mail so receivers can trust it wasn't tampered with. Required.
Bounce domain (MX)MXRoutes bounce reports back through your own domain (for example bounce.yourcompany.com), so it lines up with your From address. Recommended.
Bounce domain SPFTXTAuthorises our sending service for that bounce domain, so SPF passes for your domain. Recommended.
DMARCTXTTells receivers what to do with mail that fails the checks. Recommended.
Add exactly what the card shows, with the Type it shows — TXT, CNAME or MX. If the card lists three DKIM CNAMEs, add all three: verification only passes once every DKIM record is live.
The two bounce-domain records are recommended, not required. Your mail sends without them; adding them improves how receivers judge it.

Host or full name?

Each record shows two forms of its name:

  • Host — for example bounce or _dmarc. This is what you type in the Name / Host field at almost every DNS host, because they add your domain to the end automatically. @ means the domain itself.
  • Full name — for example bounce.yourcompany.com. Use it only if your DNS host explicitly asks for the complete name.
Typing the full name into a host that adds the domain for you creates a doubled name like bounce.yourcompany.com.yourcompany.com. If that happens, the card tells you exactly that and shows the Host value to use instead.

General steps

  1. Sign in wherever your domain's DNS is managed (your registrar or DNS host) and open the DNS / zone editor.
  2. For each record on the card, add a new record with the Type shown, the Host value as its name, and the value shown.
  3. For MX records, set the priority to 10 in the priority field — not as part of the mail server value.
  4. CNAME records must resolve as plain CNAMEs. If your DNS host offers proxying or "CNAME flattening" (Cloudflare's orange cloud is one example), turn it off for these records.
  5. Leave TTL at the default.

The card's How do I add these at my DNS host? section has steps for common DNS hosts, and shows the one we detect for your domain first. If we can't tell who hosts your DNS, it shows general steps that work anywhere.

Already have an SPF record?

A name may have only one SPF record (a TXT starting v=spf1). Two SPF records at the same name is an error, and SPF then fails for everything sent from it. If you ever need to add to an existing SPF record, edit it rather than adding a second one — the card shows a combined record you can copy when it finds two.

What the card tells you

After each check, every record says exactly where it stands:

  • Found — it's live and correct.
  • Not added yet — we can't see it at all.
  • Wrong name — we found it, but under a different name (for example a doubled one). The card shows where, and what to type instead.
  • Wrong value — it's there, but the value differs. The card shows what we found next to what it should be.
  • Two SPF records, Wrong type, Proxied, Conflicting record — explained on the record itself, with the fix.
  • DNS host didn't answer — we couldn't reach your DNS host this time, so we don't know yet. This never means you need to add anything; we'll check again automatically.

After you add them

  1. Click Check DNS. We ask your domain's own nameservers, so a record you've just added usually shows up straight away.
  2. While the domain is pending, the card keeps re-checking by itself every few seconds.
  3. Once verified, we keep checking your records daily and tell you if one stops being found.
